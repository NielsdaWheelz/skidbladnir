# native control restoration contract

[native interaction](native-agent-observation.md) owns the current capabilities;
[source qualification](native-agent-qualification.md) records the isolated new
boundaries. the dated restoration checks below remain historical evidence.

the source pin is [`deployment/native-control/helper.json`](../deployment/native-control/helper.json). the dev-server installer is the only installation owner. it upgrades a private uv bootstrap, checks out `llm-calling`'s current default-branch revision, and runs `uv sync --upgrade --extra claude-sdk --no-dev`, so the environment takes the latest python and `claude-agent-sdk` the project admits; nothing is pinned. it renders the source-owned [`skidbladnir-provider-runtime-control`](../deployment/native-control/skidbladnir-provider-runtime-control) launcher with the venv's shell-quoted absolute path as `@ENVIRONMENT_SHELL@`, installs the source-owned [`claude`](../deployment/native-control/claude) shim at that venv's `bin/claude`, and installs the launcher as the gateway generation's `providers/native-control`. the stable `~/.local/bin/skidbladnir-provider-runtime-control` symlink reaches it through `current`; that absolute public command is `nativeControlPath` in skid's host config. the [deployment handoff](dev-server-handoff.md#profiles-and-shell-defaults) owns the exact eleven-file receipt and symlink contract. the environment lives under `~/.local/share/skidbladnir/` and is skid-owned. provider binaries and the selected existing account remain shared with ordinary launches.

installation must fail before activating a gateway generation if the source revision, entry point, shim, or launcher differs or the synchronized environment does not run. stage a new revision beside the old one, then switch the gateway's `current` pointer atomically so gateway, helper launcher, shell assets, and plugin move together. retain the environments needed by prior generations for rollback. do not let a marker file alone assert an intact environment; check the revision, the executables and a rejected-request probe.

the helper's claude adapter runs `claude agents --json --all` for inspection and `claude stop <id>` for a matched background session. its source uses `asyncio.create_subprocess_exec("claude", ...)`. the launcher puts its installed shim first in `PATH`, and fails if the shim is missing. the gateway passes the selected profile's absolute native executable as `SKIDBLADNIR_CLAUDE_COMMAND`; the shim executes exactly that path, removing the dispatch variable before entering claude. a missing native executable fails inside the shim and cannot fall through to a shared `claude` later in `PATH`. the gateway clears inherited provider homes before applying the selected profile's environment, including its existing `CLAUDE_CONFIG_DIR`. the helper's subprocess inherits that home, and the pinned sdk history reader consults it. inherited `SKIDBLADNIR_SHELL` and `SKIDBLADNIR_AGENT` are removed. profile selection determines the account and executable; a generic user `PATH` or shared work wrapper cannot select either. shared account contents remain available to skid and ordinary launches; native control addresses the captured conversation independently of terminal foreground presence.

qualification on macbook, 2026-09-25: a disposable checkout at `ec97adeb9ddd0f91b141f89cc42cff7cc7efdb8f` synced with uv 0.11.28 and python 3.12.13 using the frozen claude extra. a disposable no-auth helper inspection resolved the selected claude, inherited the private config directory, and returned the documented stale result. a separate launcher/shim probe dispatched to its exact native target; removing that target or shim failed without invoking a synthetic shared claude later in `PATH`. the installed native claude 2.1.282 exposes `agents --json --all` and `stop <id>`; `agents --json --all` against an empty disposable private config returned an empty json array. the pinned sdk's session reader explicitly reads `CLAUDE_CONFIG_DIR`. these are source and no-auth compatibility checks. they do not prove live status, saved-message coverage, or stop behavior with an authenticated session. those boundaries need approved live acceptance on each host after installation.

the tradeoff is an initial download, one private python environment per retained revision, and two short installed scripts. this buys an exact source and dependency boundary without changing the shared provider installation. the adapter's literal `claude` lookup makes the shim necessary until upstream accepts an explicit executable path; native provider upgrades still need requalification.
