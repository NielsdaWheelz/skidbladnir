# devbox usage reporting cutover

problem: the fixed-devbox remaining-quota footer and publication switch are
installed, but natural callback and visible desktop acceptance remain unqualified.

impact: installation alone does not prove a natural claude-work callback reaches
the authenticated gateway or that all desktops display its remaining/reset/age
semantics correctly.

evidence: isolated source checks cover remaining/reset semantics, fixed source,
80×24 color/no-color layout and selected-row viewport. dev-server's isolated
installer/callback checks cover host selection, settings preservation and
unchanged display. on 2026-10-09, v0.14.0 was installed through managed paths on
macbook, devbox and arch. devbox's owned statusline settings enable publication;
unrelated settings are preserved. macbook/arch publication remains disabled.
no provider turn or desktop presentation check was performed in this rollout.

resolved when: a reviewed skid release and dev-server revision are installed
through their managed paths, all desktops show devbox remaining quota in the
footer/details, workstation statuslines no longer publish reports, and an actual
devbox callback is read through its authenticated gateway with the original age
and reset semantics. verification retains content-free outcomes, not quota values.

blockers: natural callback and desktop presentation acceptance are pending.
any tmux or phone work still requires explicit current-turn approval.
