problem: [source implementation and qualification](../terminal-usage.md#qualification)
are complete in the isolated skid/dev-server worktrees; the installed fleet still
runs the earlier publisher/devbox-only generation.

impact: a mixed generation of strict hosts, go clients and android cannot provide
the new optional session field and codex-only native route reliably. source
qualification does not establish managed activation or natural installed callbacks.

evidence: 2026-10-14 red/green, darwin/linux controlled gateway-to-browser,
stock-provider field/rendering, android decoder and managed installer checks are
recorded in the specification. retired readers/publishers/flags are absent from
source. old inactive-claude/devbox issues are superseded; inactive terminals now
have explicitly accepted unknown usage. release/fleet/device checks are `NOT_RUN`.

resolved when: a reviewed exact-source release and sibling installer revision are
activated through their managed paths with coordinated host/go/android consumers;
all desktops show one profile record with latest eligible source/used-versus-
remaining semantics, and ordinary installed claude callbacks are observed or
honestly omitted. verify existing provider accounts/history and terminal sessions
are preserved. optional operator cleanup removes only the fixed obsolete quota
files under configured homes; no runtime migration or compatibility path is added.

blockers: coordinated release/deployment is a separate operation under the spec.
tmux/device boundaries require explicit current-turn scope under `AGENTS.md`.
