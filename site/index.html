Skíðblaðnir

Skíðblaðnir (SKEETH-blahth-neer). Call it skid.

Every tmux session on every machine you own, on your desktop and your Android phone. The same live terminals, straight over your tailnet. Nothing hosted, no skid account, nothing to migrate.

Install: read the script, then run it

curl -fsSLO https://github.com/NielsdaWheelz/skidbladnir/releases/latest/download/install
less install
bash install

Skíðblaðnir is a single-user prototype, built and run by one person (calibration).

  • Room for all: every session on every machine.
  • A fair wind wherever it's bound: straight over your tailnet, with no relay of ours.
  • Folds into a pouch: your phone.

How it works

Install skid on each of your computers and it runs a small gateway beside that computer's tmux. The session browser (a terminal UI on any of those computers) and the Android app list every session on every computer. From either you open a terminal, or an agent such as Codex or Claude Code, and attach to the same live terminal the other sees; detach, and the work keeps running in tmux.

Each computer runs one gateway, skid serve, which controls only its own computer's tmux and reaches your tailnet through Tailscale Serve. Clients call each gateway directly; no computer relays another's terminal.

The hub is the control plane: the first computer installed, or the last to run skid recover. It holds membership, the accepted config.yaml and notification state, and it issues invitations. tmux is the data plane: it owns every session and process, and skid keeps no session database.

Lose the hub, keep the shells.

Every computer caches the membership, so its terminals stay reachable, and only edits, new devices, removals and notifications wait for the hub, or for skid recover on another computer.

skid itself hosts nothing and has no account; Tailscale needs an account, and may carry traffic through its encrypted DERP relays when no direct path exists.

Five constraints

Most of the architecture follows from five constraints.

  1. tmux is the store and the process supervisor: skid keeps no session database, and a restart re-lists tmux.
  2. Every effect is guarded in tmux on an exact lifetime and attempted at most once; a lost completion is unknown, never replayed.
  3. Execution is host-local: no gateway acts for another, no computer relays terminal bytes, and one machine's failure fences only its own rows and actions.
  4. Status, attention, usage and remote context are sampled inference: evidence for a human, never authority for an effect.
  5. One owner, one trust domain: the tailnet plus one bearer per device.

What it is not

These are non-goals, outside the scope by decision:

  • a chat interface, or provider conversation search, history, inboxes, live targeting or hooks;
  • copied provider history, state derived from transcripts, or claims that a task is done;
  • durable command receipts or replay;
  • scheduling, autonomous orchestration or a task protocol;
  • execution proxying, or moving, broadcasting, failing over or waking across machines, or automatic hub election;
  • a durable inventory, quota enforcement, or git or project discovery;
  • arbitrary host setup or tailnet policy automation, or a terminal embedded in another app;
  • containment between one user's agents, or anything multi-user.

How it compares

Remote access to coding agents sorts on three questions: who carries the bytes, who owns the process, and what the phone shows. skid answers your tailnet, your tmux, and a terminal.

  • herdr, with droidtty on Android: the most capable agent-aware multiplexer, and a native Android client for it. skid keeps tmux as the owner of your sessions, so nothing migrates and sessions outlive skid.
  • Claude Code Remote Control and Codex remote: free and first-party; traffic goes through the vendor; one provider each, in a conversation view.
  • T3 Code and Happy: polished multi-provider phone apps, with their own server or relay and a conversation view.
  • Termius or Moshi with tmux: no new software on the host; one host at a time.

Install

Mac
macOS 26 or later on Apple silicon, with Homebrew; bash or zsh.
Linux
Ubuntu 24.04 or later, or Arch Linux or a derivative; amd64 with systemd; curl and sudo; bash or zsh. Ubuntu derivatives and Debian are refused.
Phone
Android 13 or later with Google Play services, and the Tailscale app on the same tailnet.
Remote use
Tailscale, with MagicDNS and HTTPS certificates on, and on Linux with you as Tailscale's operator. skid connect points Tailscale Serve's HTTPS port 8443 at the gateway, replacing whatever it served.
Optional
Codex, Claude Code; push notifications through your own Firebase project.

On each computer, run the install commands at the top of this page.

The installer is a short Bash script that carries the release signing key, downloads this computer's archive, checks its signature and hands off to the archive's skid install, which adds tmux and Tailscale when they are missing. The Android app is not on Google Play: each release carries its APK, and Obtainium can track releases. Updates are manual: skid update on each computer, and a new APK on the phone.

Install has every step for a computer, and Phone covers sideloading, checking the signer, Obtainium and push.

When not to use skid

  • You use an iPhone. There is no iOS app.
  • Your computers run Windows, macOS before 26 or on an Intel processor, or Linux on arm64.
  • You are a team. A fleet has one owner, and every device in it can open a shell on every computer.
  • You don't use Tailscale, or you want a hosted relay.
  • You want a chat interface to your agents. The phone shows their terminals.
